# The Challenge

A major logistics provider operates a fleet of 120+ autonomous mobile robots (AMRs) across multiple warehouse facilities. These robots handle thousands of picking and transport tasks daily, making reliability critical to operations.

Before implementing Ferronyx, the operations team faced significant challenges:

- **4+ hour average debugging time** for robot incidents
- **Limited visibility** into fleet-wide performance
- **Manual log correlation** requiring SSH access to individual robots
- **No proactive alerting** - issues discovered by operators on the floor
- **Knowledge silos** - only 2-3 engineers understood the full system

<Callout type="info" title="The Impact">
With an average of 15-20 incidents per week across the fleet, the team was spending 60-80+ hours weekly just on debugging - time that could be spent improving the system.
</Callout>

## The Solution

The logistics provider implemented Ferronyx across their entire AMR fleet, focusing on three key areas:

### 1. Real-Time Fleet Observability

- Centralized dashboard showing all 120+ robots
- Instant access to logs, metrics, and sensor data
- No SSH required - everything accessible from one interface

### 2. Automated Incident Detection

- Navigation failures flagged immediately
- Sensor degradation alerts before failures occur
- Resource issues (CPU, memory, disk) detected in real-time

### 3. AI-Assisted Root Cause Analysis

- Automatic correlation of related data
- Pattern recognition across similar incidents
- Suggested causes based on historical data

## Implementation

The rollout happened in phases over 6 weeks:

**Week 1-2: Pilot**
- Deployed Ferronyx agent on 10 robots
- Validated data collection and dashboard
- Trained core operations team

**Week 3-4: Expansion**
- Rolled out to all 120+ robots
- Set up alerting and escalation workflows
- Created custom dashboards for shift supervisors

**Week 5-6: Optimization**
- Refined alert thresholds based on real data
- Built debugging runbooks
- Trained all operations staff

<Callout type="tip" title="Key Success Factor">
The pilot phase was critical. Starting with 10 robots allowed the team to validate the approach and build confidence before fleet-wide rollout.
</Callout>

When incidents occur, engineers use timeline replay to see exactly what happened:

### Cross-Robot Analysis
Pattern detection helped identify systemic issues:
- Specific warehouse zones with higher failure rates
- Correlation between deployment changes and incidents
- Time-based patterns (shift changes, lighting conditions)

## Lessons Learned

### 1. Start with the Right Alerts
Initial alert configuration was too aggressive, causing alert fatigue. After tuning:
- Critical alerts: 5-10 per day (truly urgent)
- Warnings: 20-30 per day (review in batches)
- Info: Available but not pushed

### 2. Invest in Runbooks
With faster debugging comes the need for faster resolution. The team built runbooks for:
- Top 10 failure types
- Escalation procedures
- Recovery verification steps

### 3. Share Knowledge Broadly
Previously, debugging was a specialized skill. Now:
- All operators can do first-level triage
- Shift supervisors can resolve 70% of issues
- Engineers focus on prevention and improvement
